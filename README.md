# MNGL

MNGL — C++23 header-oriented библиотека поверх SDL3 для окон, ввода, событий,
2D-рендеринга и SDL GPU. API активно развивается. Текущий Visual Studio/CMake
проект собирает демо-приложение, а не устанавливаемую библиотеку.

## Документация

Руководство находится в `docs/` и публикуется через MkDocs. Инструкция по
сборке, зависимостям и дополнительным shader-инструментам:
[`docs/getting-started/building.md`](docs/getting-started/building.md).

```powershell
python -m pip install -r requirements-docs.txt
python -m mkdocs serve
python -m mkdocs build --strict
```

Для сборки демо через Visual Studio используйте `MNGL.slnx`, платформу `x64`
и конфигурацию `Debug` или `Release`. Сборка из PowerShell:

```powershell
.\scripts\build-practicum.ps1 -Configuration Debug
```

Скрипт находит установленную Visual Studio через `vswhere` (из `Program Files
(x86)`) и запускает 64-битный MSBuild.

`MNGL.slnx` также содержит отдельные проекты алгоритмов Treap, Splay, AVL,
Red-Black, B+ и Patricia trie. Сборка решения создаёт DLL и размещает каждую
в `x64/<Configuration>/mods` с ABI-манифестом; при запуске приложения эти
моды доступны в выборе нового дерева.

Экспериментальная сборка через CMake:

```powershell
cmake -S . -B build -A x64
cmake --build build --config Debug
```

На macOS/Linux CMake ожидает SDL3, SDL3_image и FreeType, установленные в
системе или доступные через `CMAKE_PREFIX_PATH`. Кроссплатформенные сборки и
GPU-бэкенды пока требуют отдельной проверки.

## Практикум по деревьям

По умолчанию приложение запускает прототип практикума в безрамочном
полноэкранном режиме; при сворачивании или перекрытии окна рендеринг
приостанавливается до его восстановления. Explorer показывает
папки и файлы `.tree`, `.stree` и `.tar`; путь к другой папке можно ввести в
поле проводника. `.tree` хранит строковую сериализацию дерева без обёртки, а имя
задаётся именем файла. `.stree` — несжатый POSIX USTAR-архив с файлами деревьев,
истории `.htree` и манифестом `.session`; его также можно открыть архиватором,
понимающим TAR.

Файл `.tree` можно открыть кнопкой «Открыть .tree...» в панели операций,
двойным щелчком в проводнике или перетащить из файлового менеджера на окно
приложения. Каждый файл открывается в своей вкладке центрального редактора;
можно держать открытыми несколько деревьев и переключаться между ними. Звёздочка
у имени вкладки отмечает несохранённые изменения. Закрытие вкладки убирает её из
редактора, а запись остаётся в текущей рабочей области.
ПКМ по файлу в проводнике открывает команды открытия, переименования, удаления
и сохранения копии. ПКМ по узлу позволяет центрировать его или вписать всё дерево;
для ключа доступны поиск, удаление и Split.

Кнопка «Новая рабочая область» создаёт пустую виртуальную область. «Новое
дерево» создаёт пустой файл выбранного типа (тип выбирается в меню «Тип нового
дерева»); после этого можно сразу вставлять ключи. `Ctrl+S` сохраняет активный
`.tree`; для ещё не сохранённого файла открывается диалог сохранения. Пункт
«Сохранить рабочую область как .stree...» сохраняет все деревья и историю.

Открытие нескольких `.tree` не заменяет уже открытые файлы. Изменения сохраняются
отдельно для каждой вкладки, а история отмены общая: `Ctrl+Z` отменяет последнее
действие и при необходимости переключает на файл, где оно было выполнено.
Для отдельных `.tree` `Ctrl+S` сохраняет активный файл; в открытой `.stree`
сохраняется весь архив. «Сохранить рабочую область как .stree...» включает все
файлы и их текущие версии.
При открытии `.stree` все деревья архива восстанавливаются отдельными
вкладками.
Для одновременной работы с двумя деревьями нажмите «Два дерева рядом» и
выберите отдельный `.tree` в каждой панели. Масштаб и сдвиг у панелей
независимые; щелчок по панели делает её активной, и общие операции применяются
к активному дереву.

Центральное окно визуализирует дерево активной вкладки. Пустая рабочая область
показывает приглашение открыть или создать дерево. Поддерживаются BST,
AVL, красно-чёрное, Splay, Treap и B+ форматы. Узлы имеют фиксированный размер и
раскладываются по уровням; в B+ ключи-разделители находятся в отдельных ячейках,
а листья связаны `next`-стрелками. Длинные строки обрезаются с `...`, длинные
числа показываются в научной записи, полный ключ и его тип доступны во
всплывающей подсказке. Визуализатор хранит большие целые в десятичном виде и не
требует подключать Boost только ради отображения.
Модель и раскладка визуализатора кэшируются до изменения дерева или шага
анимации. Первичный расчёт видимости распределяется между основным и рабочим
CPU-потоками; при перемещении камеры рабочий поток пересчитывает видимость
асинхронно, пока UI использует последний результат. Вне области просмотра
элементы не отправляются в `Frame2D`, а hit-test использует тот же набор видимых
узлов. Небольшая область запаса вокруг камеры сокращает повторные проверки при
плавном перемещении.

Мировые координаты раскладки, камеры и отсечения хранятся в `double` на CPU.
Перед записью кадра из них вычитается позиция камеры, а длинные рёбра
обрезаются по видимой области в той же точности. На GPU передаются только
локальные координаты в `float`: это сохраняет точность текста и геометрии
на больших деревьях без требования FP64 от графического бэкенда.

Тип ключей выводится из сериализованных значений: кавычки и нечисловые токены
означают строки, дробная/экспоненциальная запись — `double`, целое вне диапазона
`int64_t` — `boost::cpp_int`. Текстовый сериализатор сохраняет дробную запись
даже для целочисленного значения `double`. В старых или вручную записанных
сериализациях, где `double` представлен целым токеном, и для `cpp_int`, который
помещается в `int64_t`, тип нельзя отличить от `int64_t`; визуализатор выбирает
`int64_t`. Примеры сериализаций, включая длинные строки, большие целые и
вложенный B+ узел, находятся в `examples/tree-practicum/`.

Поле поддерживает масштабирование колесом мыши, перемещение средней кнопкой и
подгонку кнопкой «Вписать дерево». Операции над BST, AVL, красно-чёрным, Splay,
Treap и B+ деревьями доступны для ключей `int64_t` и `double`:

| Операция | Клавиши | Алиасы в поиске функций |
| --- | --- | --- |
| `find` | `F` | `find` |
| `insert` | `A`, `Insert` | `insert`, `ins`, `add`, `put` |
| `erase` | `D`, `Delete` | `erase`, `delete`, `del` |
| `insert_random` | `R` | `insert_random`, `mass insert`, `random test`, `mass random insert` |
| `merge` | `M` | `merge`, `fast mass insert` |
| `split` | `C` | `split`, `cut` |

Горячие клавиши не срабатывают во время ввода текста или открытого диалога.
Ключ вводится в поле «Ключ»; кнопка «Найти» запускает точный поиск и подсвечивает
путь до узла (для B+ — путь до листа). Для пустого дерева тип задаётся первым
числовым вводом. В Splay поиск может поднять найденный или последний посещённый
узел в корень; такое изменение помечается несохранённым. `insert` не добавляет
дубликаты (в Splay существующий ключ при этом поднимается в корень). `erase`
удаляет ключ и восстанавливает инварианты соответствующего дерева; неуспешный
поиск при `erase` может перестроить Splay.
`merge` принимает отдельную запись `.tree` того же типа дерева и того же
числового типа ключей. Чтобы сохранить порядок, все ключи текущего дерева
должны быть меньше ключей источника; исходная запись не изменяется. `split`
по введённому pivot сохраняет две записи в рабочей области: левая содержит
ключи `< pivot`, правая — `>= pivot`. Результаты открываются как отдельные
файлы во вкладках редактора.
`insert_random` добавляет заданное число уникальных случайных ключей; случайные
дубликаты пропускаются, пока не будет вставлено точное количество. Для пустого
дерева тип ключа берётся из поля «Ключ». Массовая вставка выполняется без
анимации; формат ограничивает дерево 1 000 000 узлами, а фактическую скорость —
доступные память и время.

Алгоритмы подключены через общий полиморфный интерфейс валидации, операций и
сериализации. Вставка и удаление балансируют AVL и красно-чёрное дерево;
Treap сохраняет BST- и heap-инварианты. Для B+ дерева `merge` и `split`
перестраивают структуру из ключей листьев с сохранением fanout текущего дерева.
Splay публикует события вставки и поворотов через event manager; UI складывает
их в отдельную очередь и проигрывает по одному шагу, не задерживая синхронную
операцию над итоговым деревом. Анимация включается только для деревьев до 512
узлов и операций не длиннее 48 шагов; более крупные операции завершаются без
анимации. В сериализации красно-чёрного дерева `|1` обозначает чёрный узел, а
`|0` — красный. `Ctrl+S` сохраняет активный `.tree` или открытую рабочую
область `.stree`/`.tar`. Для сохранения всех открытых файлов и результатов
операций используйте «Сохранить рабочую область как .stree...».

Визуализатор по-прежнему показывает строки и большие целые из существующих
сериализаций, но операции интерфейса намеренно ограничены `int64_t` и конечным
`double`. Сохранение дерева и TAR-рабочей области выполняется через временный
файл с последующей заменой целевого, поэтому ошибка записи не должна обрезать
уже существующий файл. При открытии архива рабочей области или создании новой
рабочей области приложение предлагает сохранить изменения, отказаться от них
или отменить действие. Обычные `.tree` открываются рядом с текущими вкладками и
не сбрасывают их содержимое.

`Ctrl+Z` отменяет последнее действие, а `Ctrl+Shift+Z` повторяет его. История
смешивает операции над деревьями и изменения интерфейса, поэтому сочетания
отрабатывают их в обратном порядке. В историю также попадают структурные
изменения Splay, в том числе после `find` и `insert`. Пока фокус находится в поле
ввода, сочетания остаются за его встроенным редактированием. История ограничена
100 состояниями и 64 МиБ; если отдельное состояние превышает лимит памяти,
история очищается и интерфейс показывает предупреждение. `.stree` и `.tar`
сохраняют текущую рабочую область и историю undo/redo в бинарном `.htree`;
открытие архива восстанавливает активное дерево и историю, а `.htree` можно
также восстановить из проводника архива. Обычный `.tree` содержит только
сериализацию одного дерева, поэтому история в нём не сохраняется. После отмены
сохранённого действия дерево помечается как изменённое.

Панель журнала показывает структурированные записи общего логгера и использует
ту же палитру уровней, что и вывод в терминал. ANSI-цвета включаются только для
поддерживающего терминала; в Windows режим VT включается автоматически.
Перенаправленный вывод по умолчанию остаётся без цветов, а `NO_COLOR` или
`TERM=dumb` их отключает. Для принудительного включения задайте
`FORCE_COLOR=1`. Файл `last.log` содержит время и уровень записи, но не ANSI-коды;
в памяти интерфейса хранятся последние 1 000 записей.

Поддерживается USTAR без расширений GNU/PAX и без ссылок; пути внутри архива
проверяются перед отображением.

## Кроссплатформенный рендерер деревьев

`MNGL/tree_renderer.hpp` предоставляет общий полиморфный интерфейс
`mngl::two_d::tree_drawable` для бинарных деревьев поиска и B+-дерева.
`make_tree_drawable(tree)` возвращает объект с виртуальным
`draw(Frame2D&, font&, area)`. Существующие `binary_tree_drawable`,
`binary_tree_draw_options` и `make_binary_tree_drawable(tree)` сохранены для
совместимости.

```cpp
auto drawable = mngl::two_d::make_tree_drawable(tree);
drawable->draw(frame, monospace_font, mngl::rectangle{ 0.0f, 0.0f, 1.0f, 1.0f });
```

Поддерживаются AVL-, красно-чёрные, Splay- и Treap-деревья с узлами
`int64_t`, доступными через `root()`, `value()`, `left()` и `right()`, а также
`b_plus_tree<int64_t>` из `tree/b_plus_tree.hpp`. Бинарные узлы рисуются как
одна ячейка; узел B+ — как горизонтальная плашка с отдельной ячейкой для каждого
ключа. Внутренние ключи B+ показываются как разделители, ключи листьев — как
данные; горизонтальные связи между листьями включены по умолчанию и отключаются
через `tree_draw_options::show_leaf_links`.

Отрисовка использует метаданные конкретного дерева: узлы красно-чёрного дерева
заливаются красным или чёрным и подписываются `red`/`black`, AVL показывает
`h=<высота>`, а Treap — `p=<приоритет>`. Для B+ под ключами отображается тип
узла (`leaf` или `index`). У Splay-дерева нет собственного метаполя, поэтому
показывается только ключ. Высота строки метаданных, её цвет и цвета узлов RB
настраиваются через `tree_draw_options`.

Размер ячейки задаётся через `tree_draw_options::node_size`; ширина узла B+
растёт с числом ключей в нём. Связи, скруглённые узлы и текст рисуются средствами
`Frame2D`, а размер текста подбирается по измеренной ширине глифов. Камера и
область рисования остаются под контролем вызывающего кода. Адаптеры не владеют
деревом, поэтому оно должно жить дольше адаптера.

Для больших `tree_draw_model` координаты центров в `tree_layout` и общий размер
раскладки имеют тип `glm::dvec2`. `draw_tree_model_parallel()` принимает такую
модель, готовую раскладку и область `tree_draw_area` в `double`.
`tree_draw_options::coordinate_origin` задаёт вычитаемый мировой центр камеры,
а `clip_bounds` — видимую область в мировых координатах. Вызывающий код задаёт
проекцию `Frame2D` относительно этого центра; обычные `draw()`-адаптеры
сохраняют прежний интерфейс.

UI практикума находится в отдельном namespace `tree_practicum`, а не в
`mngl`. Он строит и кэширует `tree_draw_model` и раскладку, отсекает узлы и
связи вне области просмотра и рендерит оставшиеся элементы через `Frame2D` в
текстуру для ImGui canvas. Масштабирование, перемещение, подсветка узлов,
подсказки, связи листьев B+ и анимация Splay остаются частью UI; текстуры,
ImGui и GPU-вызовы выполняются на основном потоке.
