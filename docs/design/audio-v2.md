# Проектные решения аудио v2

Практическое руководство: [аудио](../core/audio.md).
v2 расширяет v1 возможностями, которые работают поверх SDL3 и SDL3_mixer и не
требуют отдельного аудио-движка.

## Цели

- дать короткий путь к захвату звука с устройства;
- добавить базовую пространственную позицию отдельного голоса;
- дать приложению push API для PCM-источника, который генерируется или приходит
  постепенно;
- сохранить SDL-типы за фасадом `mngl::audio`, кроме явно выбранных custom defines;
- не запускать пользовательский код из аудиопотока.

## Зафиксированный API

### Захват

- `try_recording_devices()` возвращает снимок подключённых устройств как
  `recording_device`; значение содержит имя и внутренний ID SDL, но не раскрывает
  SDL-типы.
- `try_open_capture(options)` использует системное устройство по умолчанию;
  overload с `recording_device` выбирает конкретное устройство. Сессия сразу
  начинает запись.
- `capture_options` выбирает частоту и 1 или 2 канала. Данные выдаются в виде
  interleaved `float` PCM. `try_read()` неблокирующе забирает всё доступное.
- `capture_session` владеет SDL audio stream и закрывает устройство при
  разрушении последнего владельца. Глобальная очистка закрывает оставшиеся
  сессии до `SDL_Quit()`.
- device values могут устареть после горячего отключения. Повторное открытие
  возвращает ошибку вместо обращения к недействительному устройству.

### Пространственное позиционирование

- `play_options::position` задаёт начальную позицию; `try_set_position()` меняет
  её во время воспроизведения. `std::nullopt` отключает пространственный режим.
- Слушатель закреплён в начале координат. Оси соответствуют правосторонней
  системе OpenGL: X вправо, Y вверх, отрицательная Z вперёд.
- SDL3_mixer сводит positioned track к моно и применяет базовую панораму и
  затухание расстояния. Настройка listener и модели затухания, эффект Доплера и
  аудиоокклюзия остаются на уровне более специализированного backend.
- Позиция может быть задана для `sound`, `music` и живого `audio_stream`.

### Живой PCM-источник

- `try_create_audio_stream(format)` создаёт push-буфер mono/stereo `float` PCM;
  `audio_stream::write(span)` добавляет interleaved samples, а
  `queued_input_frames()` сообщает объём, который ещё ожидает обработки на входе SDL.
- SDL `SDL_AudioStream` синхронизирует вход с частотой и каналами mixer в
  float-формате, который использует микшер внутри. API не вызывает
  пользовательский producer из потока микширования.
- `audio_stream::write()` разрешено вызывать из рабочего потока; остальные
  операции `mngl::audio` выполняются в основном потоке, как и в v1.
- Один `audio_stream` может быть назначен только одному активному голосу.
  Голос удерживает источник, даже если пользователь переместил или уничтожил
  wrapper. Для завершения вызывающий останавливает соответствующий
  `voice_handle`.
- Живой трек не останавливается при временно пустом буфере. Недостаточная
  буферизация создаёт слышимые паузы. Для конечных фрагментов используйте
  `sound`; для живого потока `play_options::loop` недопустим.

## Потоки и завершение

Физическое чтение capture выполняет SDL. `capture_session::try_read()` извлекает
уже полученные данные. Запись в push stream передаётся потокобезопасной функции
SDL; приложение не должно одновременно перемещать или уничтожать тот же C++
wrapper из другого потока. Producer следует остановить до завершения runtime.

Playback mixer остаётся ленивым и открывает системный output как в v1. Перечень
и открытие capture используют SDL runtime без создания playback mixer. Созданные
MNGL ресурсы освобождаются до `SDL_Quit()` даже если C++ wrapper пережил runtime;
после очистки их `try_`-операции сообщают закрытое состояние.

## Реализация и ссылки

Для захвата используется [SDL_OpenAudioDeviceStream](https://wiki.libsdl.org/SDL3/SDL_OpenAudioDeviceStream)
с `callback == nullptr`, поэтому приложение неблокирующе вычитывает готовые
данные. Для push-ввода mixer использует
[MIX_SetTrackAudioStream](https://wiki.libsdl.org/SDL3_mixer/MIX_SetTrackAudioStream);
живой track настроен продолжать работу при пустом буфере. Пространственная
обработка использует [MIX_SetTrack3DPosition](https://wiki.libsdl.org/SDL3_mixer/MIX_SetTrack3DPosition).

Это намеренно меньше полного SFML Audio API: нет перемещаемого listener,
пользовательских callback streams, seek/fade и управления устройством вывода.
Пользовательский PCM producer остаётся обычным приложением и может использовать
любой decoder или сеть, а MNGL отвечает за безопасную доставку samples в mixer.
