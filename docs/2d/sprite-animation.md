# Анимация спрайта по атласу

`mngl::sprite_animation` проигрывает последовательность регионов атласа. PNG загружается на GPU один раз, а при смене кадра меняются page handle и UV-границы спрайта. Каждый кадр может иметь собственную длительность.

Класс доступен через `<MNGL/renderer2d.hpp>`, который также включён в `render_window.hpp`. Для GIF и других файлов с готовой последовательностью кадров существует [animated_texture](../core/media-and-colors.md); этот раздел посвящён кадрам, выбранным из атласа вручную.

## Подготовка изображения

Для примера нужен файл `assets/player-strip.png` размером `256 × 64`: четыре кадра `64 × 64`, расположенные в одном горизонтальном ряду. Файл должен существовать относительно рабочего каталога запуска; он не поставляется вместе с примером.

`texture_store::region(page, uv_bounds)` принимает нормализованные границы `{u_min, v_min, u_max, v_max}`. Четверти горизонтальной полосы задаются так:

| Кадр | UV-границы | Длительность примера |
|---|---|---|
| 0 | `{0.00, 0, 0.25, 1}` | 0.10 с |
| 1 | `{0.25, 0, 0.50, 1}` | 0.10 с |
| 2 | `{0.50, 0, 0.75, 1}` | 0.18 с |
| 3 | `{0.75, 0, 1.00, 1}` | 0.10 с |

Разная длительность полезна, например, чтобы задержать фазу удара. Геометрический размер спрайта от размеров кадра в пикселях не зависит: его задаёт `sprite.destination`.

## Полное приложение

Space ставит анимацию на паузу и продолжает её, R начинает заново, Escape закрывает приложение:

```cpp
#include <MNGL/input.hpp>
#include <MNGL/render_window.hpp>
#include <MNGL/texture.hpp>

#include <exception>
#include <iostream>

int main()
{
	try
	{
		mngl::render_window window("Sprite animation", {800, 600});
		auto& atlas = window.textures();
		const auto page = atlas.add(mngl::texture("assets/player-strip.png"));

		mngl::sprite_animation walk({
		    {atlas.region(page, {0.00f, 0.0f, 0.25f, 1.0f}), 0.10},
		    {atlas.region(page, {0.25f, 0.0f, 0.50f, 1.0f}), 0.10},
		    {atlas.region(page, {0.50f, 0.0f, 0.75f, 1.0f}), 0.18},
		    {atlas.region(page, {0.75f, 0.0f, 1.00f, 1.0f}), 0.10},
		});
		mngl::sprite player{walk.current_region(), {0.3f, 0.2f, 0.5f, 0.5f}};

		while (mngl::input::next_frame())
		{
			for (const auto& keyboard : mngl::input::keyboards())
			{
				if (keyboard.pressed(mngl::scancode::space))
				{
					if (walk.playing())
						walk.pause();
					else
						walk.play();
				}
				if (keyboard.pressed(mngl::scancode::r))
				{
					walk.restart();
				}
				if (keyboard.pressed(mngl::scancode::escape))
				{
					mngl::input::request_quit();
				}
			}

			walk.update(mngl::input::delta_time());
			walk.apply_to(player);

			auto frame = window.frame(mngl::color{0.08f, 0.1f, 0.15f, 1.0f});
			frame.draw(player);
			frame.display();
		}
	}
	catch (const std::exception& error)
	{
		std::cerr << "MNGL: " << error.what() << '\n';
		return 1;
	}
}
```

Сборка и размещение runtime-файлов такие же, как в [первом 2D-приложении](quick-start.md). Если атлас не находится, сначала проверьте рабочий каталог процесса и путь к PNG.

Здесь есть три независимых объекта:

- `atlas` владеет загруженной текстурой и выдаёт регионы.
- `walk` хранит список регионов, их длительности и текущее время воспроизведения.
- `player` хранит положение, размер, поворот и оформление рисуемого объекта.

`update()` не рисует объект. `apply_to()` не продвигает время. Обе операции вызываются явно, после чего `frame.draw(player)` отправляет спрайт в кадр.

## Время и управление

Аргумент `update(delta_seconds)` — секунды, например `input::delta_time()`. Это не номер кадра, не миллисекунды и не FPS. Контроллер не подписывается на глобальный update registry: вызовите `update()` ровно в том игровом цикле, время которого должна использовать анимация.

| Операция | Результат |
|---|---|
| Конструктор | Первый кадр выбран, воспроизведение уже включено |
| `update(dt)` | Продвигает время, если анимация играет |
| `pause()` | Сохраняет кадр и накопленное время, останавливает продвижение |
| `play()` | Продолжает незавершённую анимацию |
| `restart()` | Выбирает первый кадр, сбрасывает время и запускает воспроизведение |
| `frame_index()` | Возвращает текущий индекс, начиная с нуля |
| `frame_count()` | Возвращает число кадров |
| `current_region()` | Возвращает текущий регион без изменения спрайта |
| `playing()` / `finished()` | Показывают состояние воспроизведения и завершение режима once |

Большой `dt` может перескочить через несколько кадров. Контроллер сохраняет временную скорость анимации; он не гарантирует показ каждого промежуточного изображения после задержки игрового цикла.

## Проиграть один раз

Для взрыва, появления объекта или короткого эффекта задайте режим `once` при создании. Вместо списка из полного примера можно построить вектор:

```cpp
#include <vector>

std::vector<mngl::sprite_animation::frame> frames{
    {atlas.region(page, {0.00f, 0.0f, 0.25f, 1.0f}), 0.10},
    {atlas.region(page, {0.25f, 0.0f, 0.50f, 1.0f}), 0.10},
    {atlas.region(page, {0.50f, 0.0f, 0.75f, 1.0f}), 0.10},
    {atlas.region(page, {0.75f, 0.0f, 1.00f, 1.0f}), 0.20},
};

mngl::sprite_animation effect{
    frames, mngl::sprite_animation::playback_mode::once};
```

Продвигайте `effect` теми же `update()` и `apply_to()`. Он остаётся на последнем кадре и устанавливает `finished() == true` **после истечения длительности последнего кадра**. В этот момент `playing()` становится `false`.

Игровая логика может скрыть или удалить эффект после завершения:

```cpp
effect.update(mngl::input::delta_time());
if (!effect.finished())
{
	effect.apply_to(player);
	frame.draw(player);
}
```

Этот фрагмент выполняется внутри активного кадра; для видимого финального кадра не передавайте весь цикл анимации одним большим шагом времени. Вызов `play()` после завершения once не запускает её повторно. Для повтора нужен `restart()`.

Для переключения idle/run/jump создайте контроллеры нужных клипов и выбирайте их игровой логикой. Запускайте `restart()` при смене состояния, а не каждый кадр: постоянный сброс оставит анимацию на её первом изображении.

## Как регион применяется к спрайту

`apply_to(sprite&)` копирует выбранный регион в `sprite.source` и очищает `sprite.source_texture`, переключая источник на atlas handle. Положение, destination size, tint, поворот и transform спрайта сохраняются. Поэтому один контроллер можно применить к нескольким спрайтам с одинаковой фазой, а отдельные контроллеры — к экземплярам с независимым временем.

Все регионы должны принадлежать тому `texture_store`, который использует renderer кадра. Для обычного окна создавайте их через его `window.textures()`. Handle из другого хранилища не несёт ссылки на это хранилище и не переносит текстуру автоматически.

Контроллер копирует значения регионов, но не владеет GPU-текстурами. Страницы хранилища должны существовать до отправки кадра, где они используются. `current_region()` возвращает ссылку на данные контроллера; не сохраняйте её после уничтожения самого контроллера.

## Ошибки входных данных

Конструктор отвергает пустую последовательность, невалидный page handle, нечисловые или ненормализованные UV и неположительную либо бесконечную длительность. `update()` отвергает отрицательный и нечисловой `dt`. Такие ошибки сообщаются через `std::invalid_argument`; переполнение суммарной длительности — через `std::length_error`.

Если виден неправильный участок PNG, проверьте порядок границ: это две UV-точки, а не `{x, y, width, height}`. Для кадра номер 1 из четырёх правильный диапазон `u` равен `[0.25, 0.50]`, а не `[0.25, 0.25]`.
