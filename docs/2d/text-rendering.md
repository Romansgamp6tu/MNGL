# Рендер текста

`mngl::two_d::text` — drawable, который добавляет глифы в существующий 2D-батчер. На каждый видимый глиф создаётся лёгкий quad-instance, но совместимые последовательные глифы группируются в draw calls, а не отправляются на GPU по одному. Шрифт лениво растеризует используемые глифы в текстурный атлас и переиспользует их между кадрами. Пока текст состоит из уже закешированных символов, повторная отрисовка не растеризует их и не загружает атлас заново.

```cpp
mngl::two_d::font typeface{
    mngl::gpu::device::global(),
    "imgui/misc/fonts/Roboto-Medium.ttf",
    48.0f
};

mngl::two_d::text_draw_options options;
options.height = 0.05f;
options.tint = mngl::color{ 1.0f, 1.0f, 1.0f, 1.0f };

mngl::two_d::text fps{ typeface, "FPS: 60", { 0.05f, 0.95f }, options };
window.clear();
window.draw(fps);
window.display();
```

Текст можно рисовать на `render_window` и на `mngl::texture` между её `clear()` и `display()` той же перегрузкой `draw(const drawable&)`. Объект `text` копирует переданную строку.

`height` задаёт размер шрифта в координатах 2D-сцены; `top_left` — верхний левый угол первой строки. Шрифт должен использовать тот же GPU device, что и renderer, и жить до отправки command buffer с кадром. Конструктор без `device` использует `mngl::gpu::device::global()`.

## Большие документы

Храните документ построчно и меняйте только затронутые строки. Для `text_document` требуется передать мировую область видимости: renderer вычислит диапазон строк, пересекающих её по вертикали, и пропустит остальные до разбора UTF-8 и создания глифов. Автоматического переноса строк пока нет: каждая запись документа рисуется одной строкой.

```cpp
mngl::two_d::text_document log;
log.append_line("Application started");
log.append_line("Waiting for connection...");

// Обновляем только изменившуюся строку.
log.set_line(1, "Connected");

mngl::two_d::text_draw_options options;
options.height = 0.025f;
options.clip_bounds = mngl::rectangle{ 0.05f, 0.1f, 0.9f, 0.8f };

mngl::two_d::text log_text{ typeface, log, { 0.05f, 0.9f }, options };
window.draw(log_text);
```

`clip_bounds` используется для CPU-culling и пропуска целых глифов, которые полностью вне области. Это не GPU-маска: частично выступающий глиф будет нарисован целиком. Для точного отсечения задайте `options.scissor` в пикселях render target. Для однострочного или небольшого многострочного текста передайте строку в конструктор `text`; она просматривается целиком, поэтому для больших прокручиваемых документов предпочтителен `text_document` с ограниченной областью видимости. Очень длинная отдельная строка также просматривается целиком, даже если большая часть её глифов отсечена.

## Метки сцены

Для множества надписей сначала отсеките их bounds по видимой области сцены, затем рисуйте только оставшиеся метки. `clip_bounds` ограничивает глифы одной надписи, но не заменяет пространственный индекс для сотен тысяч или миллионов меток.

```cpp
for (const scene_label& label : labels)
{
    if (!visible_world_bounds.intersects(label.bounds))
    {
        continue;
    }

    frame.draw(mngl::two_d::text{
        typeface, label.text, label.position, options });
}
```

При создании `text` из `text_document` объект документа заимствуется и должен оставаться живым до вызова `draw()`.

Каждый вызов отрисовки добавляет не более одной записи hit-test для всей надписи, а не отдельную запись на глиф. Текущая реализация раскладывает UTF-8 по кодовым точкам с базовым попарным кернингом; сложная формация письменностей, лигатуры и bidi пока не поддерживаются. Файл шрифта должен быть доверенным TrueType-файлом.
