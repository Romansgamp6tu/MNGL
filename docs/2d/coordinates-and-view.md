# Координаты и view

В MNGL размер окна, разрешение изображения и положение объекта в сцене — три разных величины. Сначала выберите единицы сцены, затем настройте камеру; размер framebuffer будет определять качество изображения.

## Три системы координат

| Значение | Единицы | Где используется |
|---|---|---|
| `window.size()` | Логические координаты окна | Размер клиентской области и координаты событий мыши SDL |
| `window.pixel_size()` / `texture.size()` | Физические пиксели render target | Разрешение GPU-изображения, scissor |
| `rectangle`, положение спрайта, `view` | Единицы 2D-сцены | Геометрия, камера, текст |

На HiDPI-дисплее логическое окно `800 × 600` может иметь framebuffer `1600 × 1200`. Переход на такой дисплей не должен удваивать размер игрока в мире.

У 2D-сцены начало координат находится в левом нижнем углу, ось `y` направлена вверх. Без пользовательского view короткая сторона цели равна `1`, а длинная определяется отношением сторон:

| Размер цели | `coordinate_size()` без view |
|---|---|
| `800 × 600` | `{1.333..., 1.0}` |
| `600 × 800` | `{1.0, 1.333...}` |
| `1024 × 1024` | `{1.0, 1.0}` |

`mngl::rectangle{0.1f, 0.2f, 0.3f, 0.4f}` означает левый нижний угол `(0.1, 0.2)`, ширину `0.3` и высоту `0.4`. Это не прямоугольник размером меньше пикселя.

## Камера в удобных единицах

### Логические координаты окна

Для простого игрового мира, где одна единица равна одной логической координате окна, задайте `logical_pixel_view()` из логического размера окна:

```cpp
#include <MNGL/view.hpp>

window.set_view(mngl::logical_pixel_view(window.size()));
mngl::rectangle player{100.0f, 100.0f, 32.0f, 32.0f};
```

Для окна `800 × 600` область мира будет `{0, 0, 800, 600}`. Координаты сцены по-прежнему начинаются снизу слева, `y` направлена вверх. Helper использует `window.size()`, а не `pixel_size()`: при HiDPI framebuffer `1600 × 1200` одна единица мира всё ещё равна одной логической координате, то есть отображается примерно в два физических пикселя.

Helper создаёт обычный `view` на момент вызова. Если окно изменяет размер, пересоздайте его из нового `window.size()` между кадрами. `view` сохраняет пропорции; если пропорции логического окна и render target различаются, видимая область немного расширится по одной оси.

### Своя область мира

Если мир удобнее описывать в метрах или условных единицах, задайте собственную область `view` между кадрами:

```cpp
#include <MNGL/view.hpp>

mngl::view camera{mngl::rectangle{0.0f, 0.0f, 16.0f, 9.0f}};
window.set_view(camera);
```

Теперь прямоугольник `{4.0f, 2.0f, 1.0f, 1.0f}` находится в этой области мира, а квадрат со стороной `1` занимает одну шестнадцатую ширины исходной камеры.

`view.area()` — запрошенная область. `view.visible_area(target_size)` — фактическая область при данном отношении сторон. MNGL расширяет область вокруг её центра по одной оси, чтобы всё заданное поле оставалось видно без растяжения:

| Цель | Фактическая область для камеры `{0, 0, 16, 9}` |
|---|---|
| `1280 × 720` | `{0, 0, 16, 9}` |
| `1200 × 600` | `{-1, 0, 18, 9}` |
| `800 × 600` | `{0, -1.5, 16, 12}` |

Это расширение видимого мира, а не letterbox-маска: на дополнительных участках можно видеть другие объекты сцены. Если вам нужны фиксированная композиция и поля по краям, сначала рисуйте её в текстуру нужных пропорций, затем разместите эту текстуру в окне.

Вызов `window.coordinate_size()` возвращает **размер** видимой области. Её начало при пользовательском view может отличаться от `(0, 0)`; для полного прямоугольника используйте `camera.visible_area(window.pixel_size())` при ненулевом размере framebuffer.

### Пиксель-перфект масштабирование

`logical_pixel_view()` не задаёт пиксель-перфект режим: его единица — логическая координата окна, а не физический пиксель framebuffer. Для пиксель-арта используйте отдельный низкоразрешённый render target, nearest-фильтрацию и вывод с целочисленным масштабом; при необходимости добавляйте letterbox-поля. Обычный `view` только сохраняет пропорции и может расширить видимую область, поэтому сам по себе не гарантирует ни целый масштаб, ни фиксированную композицию.

## Следование за игроком и приближение

`set_area()` меняет камеру. Чтобы она следовала за объектом, вычислите область вокруг центра игрока и передайте обновлённый view окну до начала следующего кадра:

```cpp
const glm::vec2 player_center = player.destination.pos + player.destination.size * 0.5f;
const glm::vec2 camera_size{16.0f, 9.0f};
camera.set_area(mngl::rectangle{player_center - camera_size * 0.5f, camera_size});
window.set_view(camera);
```

Здесь `player` — существующий `mngl::sprite`. Изменение локальной переменной `camera` само по себе не обновляет уже установленный view окна: `set_view()` сохраняет его значение.

Для приближения уменьшите `camera_size`, для отдаления увеличьте. Размеры области должны быть конечными и строго положительными. Сбросить пользовательскую камеру можно через `window.reset_view()`. `set_view()` и `reset_view()` во время активного кадра вызывают `std::logic_error`.

Окно и каждая render-target текстура хранят view независимо. Поэтому камера игры может двигаться, а отдельная текстура интерфейса сохранять фиксированную область. При `window.frame(scene_texture)` используется view текстуры.

## Из положения мыши в координаты сцены

События мыши используют логические координаты окна с началом **сверху слева**. Нельзя напрямую сравнивать их с `sprite.destination`: нужно нормализовать положение, перевернуть ось `y` и учесть видимую область камеры.

Следующая функция подходит для обычного view окна. Вызывайте её вне кадра, рисующего в другую цель:

```cpp
#include <MNGL/render_window.hpp>
#include <optional>

std::optional<glm::vec2> mouse_in_scene(const mngl::render_window& window,
                                      glm::vec2 window_position)
{
	const auto logical = window.size();
	const auto pixels = window.pixel_size();
	if (logical.x == 0 || logical.y == 0 || pixels.x == 0 || pixels.y == 0)
	{
		return std::nullopt;
	}

	mngl::rectangle visible{glm::vec2{0.0f}, window.coordinate_size()};
	if (const auto camera = window.current_view())
	{
		visible = camera->visible_area(pixels);
	}

	const glm::vec2 fraction{
	    window_position.x / static_cast<float>(logical.x),
	    1.0f - window_position.y / static_cast<float>(logical.y)};
	return visible.pos + fraction * visible.size;
}
```

Пример использования после `input::next_frame()`:

```cpp
for (const auto& mouse : mngl::input::mice())
{
	if (mouse.has_position() && mouse.window_id() == window.id())
	{
		if (const auto world = mouse_in_scene(window, mouse.position()))
		{
			// world->x и world->y заданы в тех же единицах, что и объекты сцены.
		}
	}
}
```

Для клика по повёрнутому или вложенному объекту удобнее встроенный [hit testing](hit-testing.md): он также вычисляет локальные координаты объекта и учитывает порядок рисования. Формула выше нужна для размещения объекта в мире, камеры или инструментов редактора.

## Большие координаты дерева

Расширение `extras/tree_renderer.hpp` хранит мировые центры узлов и размер раскладки в `double`. `tree_draw_area` также принимает координаты и размеры в `double`, поэтому большая раскладка не теряет расстояние между соседними узлами.

Перед отправкой геометрии на GPU из мировой позиции вычитается `tree_draw_options::coordinate_origin`; в `float` преобразуются уже локальные координаты. `clip_bounds` задаётся в мировых координатах и обрезает длинные рёбра до преобразования. GPU остаётся на FP32 и не требует поддержки FP64.

Для дерева большого размера заранее постройте раскладку и передайте мировой центр камеры как начало координат:

```cpp
auto layout = mngl::two_d::measure_tree_layout(model, options);
mngl::two_d::tree_draw_area area{0.0, 0.0, layout.size.x, layout.size.y};

options.coordinate_origin = camera_center;
options.clip_bounds = visible_world_area;
mngl::two_d::draw_tree_model_parallel(frame, typeface, model, layout, area, options);
```

Этот фрагмент предполагает уже созданные модель дерева, шрифт и параметры раскладки. Проекция кадра должна быть настроена относительно того же начала координат камеры. `draw_tree_model_parallel()` использует готовую раскладку; видимые узлы и рёбра можно предварительно вычислить через `tree_draw_culler`.
