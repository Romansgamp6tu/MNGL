# Хранилище и файлы

`<MNGL/storage.hpp>` оборачивает SDL3 store в RAII-объекты. Store задаёт корень файловых операций и закрывается при уничтожении. Имена файлов внутри него относительные; выбор физического каталога и backend зависит от типа хранилища.

## Какой интерфейс выбрать

| Задача | Интерфейс | Пример |
|---|---|---|
| Прочитать поставляемый с игрой файл | `storage::title_storage` | Текст уровня, локализация |
| Сохранить настройки или прогресс пользователя | `storage::user_storage` | Слот сохранения, рекорды |
| Открыть конкретный каталог в редакторе | `storage::file_storage` | Рабочий проект инструмента |
| Получить обычный путь для стороннего API | `paths::user_data_directory()` | Файл профиля `action_map` |
| Читать большой локальный файл в фоне | `async_io::queue` | Архив ресурсов |

`title_storage` предназначен для чтения. `user_storage` и `file_storage` позволяют читать и писать. Для простого JSON или собственного текстового формата MNGL сохраняет байты: разбор структуры, проверка версии и значения полей остаются у приложения.

## Полный пример: прочитать предыдущий слот и сохранить новый

Программа создаёт отдельное пользовательское хранилище примера. После готовности backend она ищет старый слот, печатает его в консоль и перезаписывает строкой `level=3`. Затем окно остаётся открытым до обычного закрытия.

```cpp
#include <MNGL/input.hpp>
#include <MNGL/runtime.hpp>
#include <MNGL/storage.hpp>
#include <MNGL/window.hpp>
#include <exception>
#include <iostream>

int main()
{
	try
	{
		mngl::runtime::ensure();
		mngl::window window("Storage example", {640, 360});
		mngl::storage::user_storage user("MNGL-examples", "storage-walkthrough");
		bool saved = false;

		while (mngl::input::next_frame())
		{
			if (saved || !user.ready())
				continue;

			user.create_directory("saves");
			for (const auto& item : user.enumerate("saves"))
			{
				if (item.name == "slot1.txt" &&
				    item.type == mngl::storage::entry_type::file)
					std::cout << "Previous: " << user.read_text_file(item.relative_path);
			}

			user.write_text_file("saves/slot1.txt", "level=3\n");
			user.close(); // Здесь важна возможность сообщить об ошибке завершения записи.
			saved = true;
			window.title("Slot saved; close the window");
		}
	}
	catch (const std::exception& error)
	{
		std::cerr << error.what() << '\n';
		return 1;
	}
}
```

Проверка `ready()` находится в обычном цикле, а не в бесконечном ожидании без обработки событий. Пользовательское хранилище может подключаться асинхронно. `operator bool` сообщает, что handle открыт; это не заменяет `ready()`.

В примере перед перечислением создаётся каталог, поэтому первый запуск не читает несуществующий файл. В реальной игре загруженные данные сначала проверьте и только потом меняйте игровое состояние. Ошибка чтения повреждённого слота не должна заставлять игру автоматически перезаписывать его пустыми значениями.

## Ресурсы приложения

По умолчанию `title_storage` открывает каталог данных приложения, выбранный SDL. Явный override удобен при разработке:

```cpp
#include <MNGL/storage.hpp>
#include <string>

// Функцию вызывают, когда title.ready() уже вернул true.
std::string load_dialogue(mngl::storage::title_storage& title)
{
	return title.read_text_file("dialogue/intro.txt");
}

// Внутри инициализации приложения:
void open_resource_folder()
{
	mngl::storage::title_storage title("assets");
	if (title.ready())
	{
		const auto text = load_dialogue(title);
		// Передать text системе диалогов.
	}
	// В игровом приложении неготовый title сохраняют и проверяют в следующих кадрах.
}
```

Путь `"assets"` здесь задаёт корень хранилища. Вызов `read_text_file("dialogue/intro.txt")` относится к файлу внутри этого корня. Готовый пакет приложения должен содержать соответствующие ресурсы; C++ include path или расположение исходника не определяет, откуда читаются изображения и данные.

Для пользовательских файлов конструктор без аргументов использует `APP_ORGANIZATION` и `APP_STORAGE_NAME`. Их настройка описана в [runtime и путях](runtime-and-utilities.md). Храните настройки приложения в одном стабильном namespace организации/имени, чтобы обновление версии не создавало новый пустой профиль.

## Чтение, запись и перечисление

| Метод | Тип результата и назначение |
|---|---|
| `read_file(path)` | `std::vector<std::byte>` с полным содержимым |
| `read_text_file(path)` | `std::string` с теми же байтами; без разбора JSON и смены кодировки |
| `write_file(path, bytes)` | Создаёт или полностью перезаписывает файл из `std::span<const std::byte>` |
| `write_text_file(path, text)` | Записывает байты `std::string_view` |
| `create_directory(path)` | Создаёт отсутствующие родительские каталоги |
| `enumerate(directory)` | Непосредственные записи одного каталога, без рекурсивного обхода |
| `close()` | Закрывает store и сообщает ошибку SDL через исключение |

`entry` содержит `name`, `relative_path`, `type` и `size`. Для чтения найденного файла используйте `relative_path`: он уже включает имя перечисленного каталога. Размер записи полезен для UI; для чтения файла произвольного размера всё равно нужно учитывать доступную память.

Например, этот фрагмент внутри функции выводит только файлы указанного каталога; нужны `<iostream>` и готовый `user`:

```cpp
for (const auto& item : user.enumerate("saves"))
{
	if (item.type == mngl::storage::entry_type::file)
		std::cout << item.relative_path << " (" << item.size << " bytes)\n";
}
```

## Пути и типичные ошибки

Внутри store используйте `/` и путь от его корня. Пустая строка разрешена только для перечисления корня: `store.enumerate()`. Компоненты `.`, `..` и пустые компоненты запрещены, как и нулевой символ.

| Путь | Результат |
|---|---|
| `"saves/slot1.txt"` | Корректный относительный путь |
| `"saves\\slot1.txt"` | Ошибка: обратный слеш |
| `"/slot1.txt"` или `"C:/saves/slot1.txt"` | Ошибка: абсолютный путь |
| `"saves/../slot1.txt"` | Ошибка: выход через `..` |
| `"saves//slot1.txt"` | Ошибка: пустой компонент |

Ошибки аргументов приводят к `std::invalid_argument`. Доступ до готовности или после закрытия приводит к `std::logic_error`. Отказ backend, отсутствие файла и ошибки чтения/записи обычно сообщаются через `mngl::sdl_error`. Если приложение допускает отсутствие сохранения, сначала перечислите каталог или обработайте отказ и покажите пользователю понятный результат.

Запись перезаписывает файл; публичный store API не обещает транзакционность нескольких файлов или атомарную замену слота. При проектировании формата сохранения отделяйте подготовку данных от записи и проверяйте успешное завершение. Для важных данных вызовите `close()` явно, пока приложение ещё может сообщить об ошибке: деструктор не бросает исключений. Закрытие освобождает handle даже при ошибке backend, повторять запись через этот объект уже нельзя.

Store имеет move-only владение. Не сохраняйте `raw()` после его закрытия или перемещения. Закрывайте хранилище до завершения SDL; локальный объект внутри `main()` обычно даёт нужный порядок разрушения.

## Локальный каталог и большие файлы

`file_storage(root)` полезен редактору, который открывает выбранный пользователем проект. Пример ниже требует существующего каталога `projects/demo`:

```cpp
mngl::storage::file_storage project("projects/demo");
if (project.ready())
{
	project.create_directory("exports");
	project.write_text_file("exports/manifest.txt", "format=1\n");
	project.close();
}
```

Чтение и запись store синхронны. Для большого локального архива рассмотрите [асинхронный ввод-вывод](async-io.md). Он принимает обычные файловые пути и не подменяет backend `title_storage` или `user_storage`. Для настройки клавиш с готовым сохранением в файл см. [профили ввода](input-recipes.md#input-profile-storage).
