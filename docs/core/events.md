# События

`mngl::event_manager` преобразует события SDL в типизированные структуры MNGL. Подписка задаётся типом события и callback-функцией:

```cpp
auto resize_subscription = mngl::event_manager::on<mngl::window_resized>(
    [](const mngl::window_resized& event)
    { logger.info("Window size: ", event.size.x, " x ", event.size.y); });
```

Структуры событий для окна, клавиатуры, мыши, дисплеев, gamepad/joystick, touch, буфера обмена, drag-and-drop, аудиоустройств, сенсоров и других событий находятся в `event.hpp`. `clipboard_update` сообщает, изменилось ли содержимое внешним приложением, и содержит список MIME-типов. Большинство событий окна наследуются от `window_event` и содержат идентификатор окна; конкретные события добавляют свои данные.

Для обычного приложения достаточно цикла `input::next_frame()`: он обрабатывает очередь SDL, после чего подписчики получают события в потоке этого вызова. Вызов `mngl::poll_events()` тоже прокачивает очередь и доставляет ожидающие события, не начиная новый кадр. `input` также предоставляет упрощённый доступ к состоянию клавиатуры и мыши, если не нужна событийная модель.

`on<T>()` возвращает move-only `mngl::event_connection`. Подписка активна, пока живо это соединение; уничтожение или `disconnect()` отключает её. Поэтому результат `on()` нужно сохранить, иначе временное соединение сразу отключит callback. Если отключение вызвано из другого потока, оно дождётся уже выполняющегося callback; сам callback может отключить свою подписку, в том числе при вложенной отправке события.

SDL вызывает внутренний watcher при добавлении события в очередь, иногда из потока, который его добавил. Watcher MNGL только сохраняет типизированную копию события; пользовательские callbacks выполняются позже при `input::next_frame()` или `mngl::poll_events()` в потоке прокачки. Исключение callback проходит через этот обычный вызов C++ и не пересекает границу SDL callback. `event_manager::emit()` для события, созданного приложением, остаётся синхронным и вызывает callback в потоке самого `emit()`.

Не захватывайте в callback объекты по ссылке, если они могут быть уничтожены раньше соединения. Callback получает событие как `const`-ссылку и не должен сохранять эту ссылку после возврата.

Типизированный интерфейс также позволяет объявить собственный тип, унаследованный от `mngl::event_base`, зарегистрировать на него `on<T>()` и отправлять его через `event_manager::emit()`.

## Отдельная шина для подсистем

Для собственных событий подсистем можно создать `mngl::event_bus`. У каждого экземпляра свой набор подписок: событие одной шины не вызывает callbacks другой шины или глобального `event_manager`.

```cpp
struct score_changed : mngl::event_base
{
	int score{};
};

mngl::event_bus gameplay_events;
mngl::event_bus interface_events;

auto gameplay_score = gameplay_events.on<score_changed>(
    [](const score_changed& event) { update_score(event.score); });
auto interface_score = interface_events.on<score_changed>(
    [](const score_changed& event) { refresh_score_label(event.score); });

score_changed changed{};
changed.score = 100;
gameplay_events.emit(changed); // Только gameplay_score.
```

Локальный `emit()` синхронен: callback работает в потоке вызова. `event_bus` не получает SDL-события и не связан с глобальным менеджером. Для пользовательских событий пока нет `post()` или автоматической передачи callback в главный поток; очередь имеет смысл, когда появится конкретный сценарий отправки событий из рабочего потока. `clear()` отключает подписки, а уничтожение шины тоже отключает соединения.
