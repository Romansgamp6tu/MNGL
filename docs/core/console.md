# Реестр консольных команд

`mngl::console::registry` хранит описания команд и вызывает их обработчики с типизированными аргументами. `mngl::console::dispatcher` использует этот же реестр для разбора команд из `argc/argv` или строки, переданной из режима `--console`.

Аргументы объявляются в порядке вызова обработчика. `argument<T>()` добавляет позиционный параметр; сейчас поддерживаются `std::string`, целочисленные типы до 64 бит и `float`/`double`. Целые числа хранятся в `argument_value` как `std::int64_t`, а числа с плавающей точкой — как `double`; при вызове проверяется диапазон целевого типа. `flag()` добавляет необязательный булев флаг вида `--name` со значением по умолчанию `false`.

```cpp
#include <MNGL/console.hpp>

#include <cstdint>
#include <iostream>
#include <string>
#include <utility>
#include <vector>

mngl::console::registry commands;

commands.add_command("greet", "Поприветствовать пользователя")
    .argument<std::string>("name", "Имя пользователя")
    .argument<std::int64_t>("count", "Количество повторений")
    .flag("loud", "Добавить восклицательный знак")
    .handler(
        [](const std::string& name, std::int64_t count, bool loud)
        {
	        std::string output;
	        for (std::int64_t i = 0; i < count; ++i)
	        {
		        output += "Привет, ";
		        output += name;
		        output += loud ? "!\n" : ".\n";
	        }
	        return mngl::console::command_result{std::move(output), 0};
        });
```

Хост передаёт в `invoke()` все значения в том же порядке, включая `false` для неуказанного флага, и получает результат команды:

```cpp
const std::vector<mngl::console::argument_value> arguments{std::string{"Мир"}, std::int64_t{2}, true};
const auto result = commands.invoke("greet", arguments);
std::cout << result.stdout_text;
```

`command_result::stdout_text` и `stderr_text` содержат текст для соответствующих потоков, а `exit_code` — код завершения команды. Обработчик может вернуть `command_result`, строку или ничего; строка нормализуется в результат с нулевым кодом, `void` означает пустой вывод. Реестр проверяет существование команды, количество и типы аргументов. Ошибки регистрации и проверки аргументов выбрасываются как `registry_error`, у которого можно прочитать `code()` и `command_id()`. При прямом вызове `registry::invoke()` исключения обработчика передаются вызывающему коду.

`find()` возвращает описание одной команды, а `commands()` — копии всех описаний, отсортированные по ID. Это даёт оболочке доступ к именам, типам, описаниям и значениям флагов без доступа к внутреннему обработчику.

## Диспетчер

`dispatcher` принимает стандартные аргументы `main` (с `argv[0]`) или строку команды. В строке пробелы разделяют токены, одинарные и двойные кавычки сохраняют пробелы внутри значения. Вне кавычек обратная косая черта экранирует пробелы и кавычки; в двойных кавычках — двойную кавычку и саму себя. В остальных случаях она сохраняется, поэтому Windows-пути остаются целыми. Это только разбор аргументов: подстановки и другие возможности Bash/PowerShell не выполняются.

```cpp
int run_cli(const mngl::console::registry& commands, int argc, char** argv)
{
	mngl::console::dispatcher cli{commands};

	// Прямой запуск: app greet Мир 2 --loud
	const auto result = cli.dispatch(argc, argv);
	std::cout << result.stdout_text;
	std::cerr << result.stderr_text;
	return result.exit_code;
}

// Тот же разбор для текста из собственного режима --console
auto console_result = mngl::console::dispatcher{commands}.dispatch("greet \"Мир с пробелом\" 2 --loud");
```

Для готового `main()` используйте `run_process()`: он печатает результат и возвращает код завершения. По умолчанию результат человекочитаемый: `stdout_text` идёт в stdout, `stderr_text` — в stderr. Запуск `app greet Мир 2 --loud` выполняет одну команду. Форма `app --console "greet Мир 2 --loud"` также выполняет одну команду, разбирая содержимое строки.

Добавьте `--json` перед командой, чтобы получить JSON-объект в stdout:

```sh
app --json greet "Мир" 2 --loud
```

Схема ответа постоянна: `exit_code` — код команды, `stdout` и `stderr` — её текстовые потоки. Текст обработчиков в JSON-режиме должен быть в UTF-8; переводы строк и управляющие символы экранируются по правилам JSON, как и кавычки с обратными косыми чертами.

```json
{"exit_code":0,"stdout":"Привет, Мир!\nПривет, Мир!\n","stderr":""}
```

Флаг относится к запуску диспетчера и указывается до команды; `dispatch()` продолжает возвращать `command_result`, форматирование делает `run_process()`. Его можно задать и через `stream_options::format`, если хост вызывает API напрямую.

Если передать только `app --console`, `run_process()` читает stdin построчно и выполняет все команды в рамках того же `dispatcher` и реестра. Так обработчики могут управлять одним и тем же состоянием приложения между вызовами. Пустые строки пропускаются, `:quit` и `:exit` завершают поток. По умолчанию ошибка одной команды выводится, после чего читается следующая строка; итоговый код процесса будет ненулевым, если хотя бы одна команда завершилась ошибкой. Опция `stream_options{ .stop_on_error = true }` прекращает чтение после первой ошибки. Потоковый ввод и вывод можно передать явно, а `run_stream()` возвращает `stream_result`: `commands_processed` учитывает все разобранные непустые команды, `commands_failed` — команды с ненулевым кодом, `quit_requested` показывает, встретилась ли команда выхода, `exit_code` содержит итоговый код.

Чтобы весь поток выдавал машинно-читаемые ответы, запустите `app --json --console` (порядок `--console --json` тоже поддерживается). На каждую команду выводится одна JSON-строка с той же схемой; таким образом, поток является NDJSON. В Bash ввод можно передать через pipe:

```sh
printf 'greet Ada 1\n:quit\n' | app --json --console
status=$?
```

PowerShell сохраняет строки команд в файле и передаёт их приложению:

```powershell
Get-Content .\commands.txt | & .\app.exe --json --console
$exitCode = $LASTEXITCODE
```

`run_process()` возвращает код команды или итоговый код потока из `main()`. Оболочка получает его как exit code процесса: в Bash — `$?`, в PowerShell — `$LASTEXITCODE` (переменная `$?` в PowerShell означает только успешность последней команды).

Полный собираемый пример с командами `echo`, `sum` и `status`, конфигурацией CMake и примерами запуска в Bash/PowerShell находится в `examples/console/`.

```cpp
int main(int argc, char** argv)
{
	mngl::console::registry commands;
	// Зарегистрировать команды и обработчики, при необходимости захватывающие
	// состояние приложения.

	return mngl::console::dispatcher{commands}.run_process(argc, argv);
}
```

При необходимости хост может передать собственные потоки:

```cpp
const int exit_code = cli.run_process(argc, argv, input, output, error);
```

Флаги можно указывать до или после позиционных аргументов; `--` завершает список опций, чтобы передать строку, начинающуюся с `--`, как позиционный параметр. Целые числа разбираются как десятичные `int64_t`, числа с плавающей точкой — как конечные `double`. Для булевых флагов принимается только форма `--name`, повторный флаг считается ошибкой.

Диспетчер автоматически показывает общий список команд для `--help`/`-h`, а детали команды — для `--help <command>` и `<command> --help`. Имя флага `help` зарезервировано. Ошибки разбора и неверные параметры возвращаются в `stderr_text` с кодом `2`; исключения обработчика — с кодом `1`. Успешный вызов и справка имеют код `0`. В человекочитаемом режиме `run_process()` направляет `stdout_text` и `stderr_text` в соответствующие потоки; в JSON-режиме оба поля входят в объект ответа, печатаемый в stdout. Код команды возвращается процессу как exit code.
