# Разбор ошибок и частые вопросы

Проверяйте приложение по слоям: сборка → загрузка библиотек → создание обычного окна → GPU → собственные данные. Если обычный `mngl::window` работает, а `render_window` падает, текст ошибки уже относится к более узкой части запуска.

## Как получить полезное сообщение

В полных примерах есть `catch (const std::exception& error)`. Запускайте программу из терминала, чтобы увидеть `error.what()` до закрытия окна консоли. Текст `sdl_error` содержит контекст операции и место, где ошибка была сформирована; копируйте сообщение целиком.

Для поиска проблем с assets полезно один раз вывести оба каталога:

```cpp
#include <MNGL/paths.hpp>
#include <filesystem>
#include <iostream>

std::cout << "Working directory: " << std::filesystem::current_path() << '\n';
std::cout << "Application directory: " << mngl::paths::application_directory() << '\n';
```

Это фрагмент для `main()` внутри `try`. Полный стартовый проект есть в [быстром старте](../2d/quick-start.md).

## Программа не компилируется

| Симптом | Проверка | Исправление |
|---|---|---|
| `MNGLConfig.cmake` не найден | Распакован ли development-пакет, а не runtime? | Укажите его корень в `CMAKE_PREFIX_PATH` либо каталог config в `MNGL_DIR` |
| Не найден `<MNGL/...>` | Привязан ли target приложения к `MNGL::MNGL`? | Используйте `target_link_libraries(app PRIVATE MNGL::MNGL)` |
| Нет `std::expected`, `std::format` | Версия компилятора, стандартной библиотеки и режим языка | Нужен C++23; CMake target MNGL передаёт это требование |
| Метод из примера отсутствует | Версия заголовков в пакете и документации | Сверьте пакет с исходниками; свежие `sprite_animation`, профили действий и `wrap_width` могут отсутствовать в старом релизе |
| `LNK2019`/`undefined reference` к SDL или ImGui | Линковка target, архитектура и конфигурация | Используйте экспортированные CMake targets и библиотеки той же архитектуры |
| Не найдены `MIX_*` | Включён ли аудиослой и доступен ли SDL3_mixer | Настройте [SDL3_mixer](../core/audio.md#sdl3-mixer) или выбранную конфигурацию отключения аудио |

Сначала соберите пример без изменений. Затем добавляйте по одной зависимости: так видно, какая настройка привела к ошибке. Ручное добавление include directory не заменяет линковку библиотек и compiler definitions.

## Программа собирается, но не запускается

`CMAKE_PREFIX_PATH` помогает CMake при сборке. Загрузчик ОС ищет DLL/`.so` при запуске отдельно. На Windows разместите runtime DLL рядом с приложением либо добавьте каталог пакета `bin` в `PATH` для текущего терминала. На Linux настройте установку библиотек или путь загрузчика согласно [подключению MNGL](using-mngl.md#configuration-and-run).

Используйте development- и runtime-файлы одной версии и архитектуры. Сообщение о несовместимой архитектуре нельзя исправить добавлением ещё одного include path.

## Обычное окно есть, GPU-окно не создаётся

`window` использует оконный слой; `render_window` дополнительно создаёт GPU-ресурсы и 2D renderer. Проверьте:

1. Точное исключение: ошибка создания устройства, загрузки шейдера и компиляции pipeline требуют разных исправлений.
2. Доступность GPU backend на текущем компьютере и драйвере.
3. Наличие встроенного каталога `shaders/` из совместимого runtime и путей к shader tools.
4. Рабочий каталог, каталог приложения и выбранные настройки shader loader.

Начните с [первого 2D-приложения](../2d/quick-start.md), которое рисует цветную фигуру и не зависит от пользовательских картинок и шрифтов. Для настройки компилятора и форматов шейдеров используйте [руководство по шейдерам](../gpu/shaders.md).

## Окно чёрное или объект не виден

| Причина | Что сделать |
|---|---|
| Кадр открыт, но не отправлен | Вызвать `frame.display()`; уничтожение scope отменяет кадр |
| Координаты заданы в пикселях для стандартного view | Короткая сторона сцены по умолчанию равна `1`; проверить `coordinate_size()` или настроить `view` |
| Объект за границей камеры | Проверить `destination`, `transform` и фактическую область `view::visible_area()` |
| Прозрачный tint | Проверить альфа-канал цвета и параметр прозрачности |
| Текстура или шрифт уже уничтожены | Хранить ресурс до отправки кадра, не возвращать спрайт со ссылкой на локальную текстуру |
| Текстура offscreen ещё рисуется | Закончить её кадр перед чтением из неё как из спрайта |
| Atlas handle взят из другого store | Получать регионы через `textures()` того renderer/context, где их будут рисовать |

Если изображение вверх ногами или мышь выбирает другой объект, проверьте начало координат: события мыши используют верхний левый угол, сцена MNGL по умолчанию — нижний левый. Готовый перевод приведён в [координатах и view](../2d/coordinates-and-view.md).

## Изображение, звук или шрифт «не найден»

Относительный путь привязан к рабочему каталогу. Самая частая ошибка — запуск из `build/Release` при assets, лежащих в каталоге исходников. Выведите пути из первого раздела и проверьте файл именно по полученному абсолютному пути.

Файлы приложения не копируются в сторонний проект только от линковки `MNGL::MNGL`. Добавьте копирование assets в собственную сборку или используйте каталог ресурсов приложения. Шрифт тоже является файлом приложения; наличие текста в коде не загружает font автоматически.

Для пользовательских сохранений используйте `paths::user_data_directory()`, а не каталог assets. Если после изменения имени приложения пропали настройки, проверьте `APP_ORGANIZATION` и `APP_STORAGE_NAME`.

## Нажатие срабатывает постоянно или пропадает

Для переключателя нужна `pressed()`, для движения при удержании — `down()`. `released()` показывает отпускание. Обновляйте ввод одним `input::next_frame()` в начале итерации; второй вызов начнёт другой кадр и сменит однокадровые состояния. Собственный `SDL_PollEvent()` также забирает события из общей очереди.

`input::keyboard()` по индексу бросает `std::out_of_range`, если устройства нет. При допустимом отсутствии клавиатуры перебирайте `input::keyboards()` или используйте `action_map` с несколькими источниками. Сохранённый SDL device ID не является постоянным номером физического устройства между запусками; для обычного профиля оставляйте device filter пустым.

Действия не выключаются автоматически из-за захвата Dear ImGui. Переключайте `input_context::set_enabled()` согласно UI-режиму приложения. Примеры паузы и профилей находятся в [рецептах ввода](../core/input-recipes.md).

## Анимация или движение идут слишком быстро

Умножайте скорость на `delta_time()` в секундах. `sprite_animation::frame::duration_seconds` также использует секунды: `0.1` — десять кадров в секунду для равномерной последовательности, `100` — сто секунд на один кадр.

Проверьте, что `sprite_animation::update()` вызван ровно один раз за игровой шаг. Для переноса выбранного кадра в спрайт вызовите `apply_to()` перед рисованием; иначе изменится состояние контроллера, но спрайт сохранит старый источник.

## Как подготовить воспроизводимый пример

Приложите версию/commit MNGL, ОС и архитектуру, компилятор и CMake-конфигурацию, полное сообщение ошибки и короткий `main.cpp`. Для проблем ресурсов укажите рабочий каталог и структуру assets; для GPU — используемый backend и этап, на котором произошёл сбой. Удалите из примера нерелевантные сцены, оставив один объект или одну операцию.

Для сравнения используйте [готовые учебные проекты](https://github.com/Romansgamp6tu/MNGL/tree/V-0.2.3-a/examples): окно с фигурой и действия ввода не требуют пользовательских assets. Это помогает отличить проблему окружения от ошибки в собственном коде.
