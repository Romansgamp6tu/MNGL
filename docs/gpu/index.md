# Низкоуровневый GPU API

`mngl::gpu` даёт явный контроль над GPU-ресурсами и порядком команд. Начните с [2D API](../2d/index.md), если нужно вывести спрайт, текст, фигуры или интерфейс. К GPU-слою удобно переходить, когда нужны собственный vertex layout, compute-обработка, необычный pipeline или несколько зависимых проходов.

## Какие объекты участвуют в кадре

| Объект | Его задача | Когда создавать |
|---|---|---|
| `device` | Выбирает GPU backend и владеет SDL GPU device | Обычно один раз |
| `buffer`, `texture`, `sampler` | Хранят данные и настройки чтения | При загрузке или изменении размеров |
| Shader asset | Хранит байткод, layout и CPU-значения параметров | При загрузке шейдера |
| Graphics/compute pipeline | Фиксирует программу и совместимый GPU state | При загрузке или смене layout/формата |
| `command_buffer` | Записывает операции, которые будут отправлены вместе | Для очередной загрузки или кадра |
| Render/compute pass | Задаёт контекст bindings и draw/dispatch | Внутри command buffer |

Создание ресурса не означает, что GPU уже получил его содержимое. Например, `buffer::upload()` записывает копирование в command buffer; работу запускает `commands.submit()`. Аналогично, завершение прохода закрывает список его команд, но само по себе не отправляет их.

## Порядок изучения

1. [Устройство и команды](device-and-commands.md): запустить пример без шейдеров, понять `submit()`, отмену и потоки.
2. [Ресурсы](resources.md): загрузить массив вершин, изменить диапазон и выбрать usage-флаги.
3. [Шейдеры](shaders.md): получить asset и GPU shader, подготовить shader tools.
4. [Pipeline и проход](pipelines-and-passes.md): согласовать структуру вершины с шейдером и записать треугольник.
5. [Compute](compute.md): заполнить текстуру на GPU и показать её обычным спрайтом.
6. [Граф кадра](frame-graph.md): описать зависимости, когда проходов и временных ресурсов становится много.

Примеры с `int main()` — законченные C++-программы; им нужен проект, связанный с `MNGL::MNGL`, как в [руководстве по подключению](../getting-started/using-mngl.md). Остальные фрагменты явно перечисляют объекты, которые нужно создать заранее. Компиляция HLSL/GLSL при запуске дополнительно требует инструментов из [руководства по шейдерам](shaders.md).

## Две текстуры с похожими именами

`mngl::texture` загружает изображения, обновляет пиксели и предоставляет 2D render lifecycle. `mngl::gpu::texture` — ресурс SDL GPU с размером, форматом и usage; он сам не загружает PNG и не рисует спрайт.

Слои можно сочетать. Например, compute pass записывает в `mngl::texture`, а затем `mngl::sprite::borrowed()` показывает render target через обычный `window.frame()`. Изображения-ассеты добавляйте в `window.textures()` и создавайте спрайты из выданного handle. Для доступа к низкому уровню у высокоуровневой текстуры есть `raw_gpu_texture()`.

## Три проверки перед каждым GPU-примером

Устройство у ресурсов и command buffer должно совпадать. Usage должен разрешать все операции, для которых создаётся ресурс. Проход должен завершиться до отправки command buffer. Эти три условия объясняют значительную часть ошибок при переносе фрагментов в приложение.

Все имена заголовков в этом разделе публичные: подключайте `<MNGL/gpu_buffer.hpp>`, а не файлы из `MNGL/detail/`.
